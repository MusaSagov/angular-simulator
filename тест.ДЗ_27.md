13.Когда выполняется inject(A), Angular проходит цепочку зависимостей лениво, сверху вниз: сначала ищет A, затем при создании A запрашивает B, затем C, затем D, затем LoggerService. Все root-провайдеры кэшируются в корневом инжекторе, поэтому каждый сервис создаётся один раз и переиспользуется дальше.

15.
 1. ApiService - providedIn: 'root'-	один HTTP-клиент на всё приложение.
 2. AuthService - providedIn: 'root' - Текущий пользователь и auth-состояние должны быть общими для приложения
 3. CartService - providedIn: 'root' - Корзина обычно должна сохраняться между страницами в рамках одной сессии приложения
 4. ProductFilterService - providers роутинга Фильтры должны быть отдельными для маршрутов и исчезать при уходе со страницы; route providers scoped к маршруту
 5. NotificationService providedIn: 'root' Toast-уведомления нужны из любого места приложения
 6. ThemeService - providedIn: 'root' Тема должна быть общей для всех страниц
 7. DashboardStatisticsService providers компонента или роутинга. Сервис нужен только для Dashboard и не должен жить вне этой области; route providers подходят, если он завязан на страницу
 8. UserTableStateService providers компонента или роутинга состояние таблицы нужно только внутри страницы пользователей
 9. ModalService - providedIn: 'root'- любой компонент должен уметь открыть модальное окно
 10. LoggerService - useFactory + providedIn: 'root' или provider с useFactory.В production и development нужна разная реализация,поэтому подходит фабрика 
 11. AppConfig - InjectionToken + useValue - это не сервис, а конфигурационные данные.
 12. CurrencyFormatter - InjectionToken или useValue если это просто формат/шаблон числа, удобнее хранить как значение через токен
 13. AnalyticsService - useFactory + InjectionToken или условный provider сервис должен существовать только при включённой аналитике
